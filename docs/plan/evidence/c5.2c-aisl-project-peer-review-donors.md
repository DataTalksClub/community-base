# C5.2c AISL donor analysis: projects and peer review

Donor inventory for issue C5.2c, step 4. Scope: models and behavior only; no code moves and no
equivalence checks in this milestone. Donor repository: `AI-Shipping-Labs/website`.

Donor files

- `content/models/peer_review.py`: `ProjectSubmission`, `PeerReview`, `CourseCertificate`.
- `content/services/peer_review_service.py`: `PeerReviewService` (batches, assignment, rollup,
  certificates).
- `content/views/peer_review.py`: submission and review entry flows (web and API).
- `content/models/course.py`: course-level peer review settings.

## Behavior (`PeerReviewService`)

- Batch formation, cohort mode: cohorts whose `end_date` has passed, submissions still in
  `submitted`, batched when at least 2 exist.
- Batch formation, self-paced mode: submissions with null cohort accumulate in a waiting pool and
  batch when the pool reaches `peer_review_count + 1`.
- Trigger: management command `form_review_batches` over courses with `peer_review_enabled`;
  intended for hourly cron.
- Assignment: round-robin; submission i is reviewed by students of submissions at offsets
  1..min(`peer_review_count`, n-1) modulo n; `PeerReview` rows via `get_or_create`.
- On assignment: submission status becomes `in_review`, `batch_assigned_at` and
  `review_deadline` are set, on-platform notifications go out with per-student outstanding
  counts.
- Rollup: when every review of a submission is complete, status becomes `review_complete`, the
  submitter is notified, and certificate eligibility is re-checked.
- Certificate eligibility: all course units completed, submission exists, all reviews assigned to
  the student are complete, at least one received review and all received reviews complete. On
  pass: `CourseCertificate` is created, submission becomes `certified` with
  `certificate_issued_at`, notification sent.
- `issue_certificates_for_course` re-runs eligibility for all non-certified submissions.

No numeric project score, no aggregate evaluation score, no leaderboard: the only scored artifact
is the optional 1..5 review score, and the only gate is certificate eligibility.

## Mapping to `community_base.coursework` (C5.2a models)

Per issue step 4: the AISL light `ProjectSubmission`/`PeerReview` become a `Project` per cohort
with the same criteria text; A5.1 applies the mapping at adoption.

- AISL course-level settings become per-cohort `Project` rows: `peer_review_count` maps to
  `number_of_peers_to_evaluate`; the derived batch deadline (assignment + `peer_review_deadline_days`
  days) is replaced by the explicit `peer_review_due_date`; `peer_review_criteria` text carries
  over as `ReviewCriteria` descriptions assigned through `ProjectCriteriaAssignment`. AISL's
  single shared rubric has no option/score structure; structured criteria come from the DTC donor.
- AISL `ProjectSubmission` maps to package `ProjectSubmission` with scope changes: per
  `Project` + `Enrollment` instead of per course + user; `project_url` becomes `github_link` plus
  `commit_id` (AISL has no commit capture); AISL's description-only text maps to the
  `problems_comments` / FAQ fields only loosely; learning-in-public and scoring fields have no
  AISL source and stay package-native.
- AISL submission status lifecycle has no direct package counterpart: the package expresses the
  same outcomes through `reviewed_enough_peers`, `passed`, and `volunteer_review_only` plus
  `PeerReview.state`. Certificate status is a certificates-capability concern, not coursework.
- AISL `PeerReview` maps to package `PeerReview` (`state` TR/SU instead of `is_complete`); AISL's
  optional 1..5 `score` maps to per-criterion `CriteriaResponse` rows rolled up into
  `ProjectEvaluationScore`; AISL's required free-text `feedback` maps to `note_to_peer`. Package
  additions with no AISL source: reviewer-side learning-in-public links, time spent, and
  problems/comments.
- AISL round-robin batch formation is the required-review half of C5.2c step 2; volunteer reviews
  come from the DTC donor. AISL self-paced micro-batching has no package equivalent because
  package `Project` is always per cohort; flag for A5.1 adoption decisions.
- AISL notifications (batch ready, reviews complete, certificate earned) map to package mail/jobs
  purposes following the C5.2b reminder pattern.
- `CourseCertificate` and unit-completion gating have no coursework counterpart; out of C5.2c
  scope. Not run here, needs: adoption-time decision in A5.1 on certificate linkage.
