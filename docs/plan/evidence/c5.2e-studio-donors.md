# C5.2e studio donor analysis

Source: `dtc-website` `studio_courses/` at the C5.2e start commit. Scope decision: the
issue verification names homework rescoring, peer review administration and leaderboard
recompute; donor capabilities outside that scope are recorded as not ported with the
reason.

## Donor inventory

- Services `studio_courses/services.py`: `update_homework_submission_from_admin` (answers,
  rescore, score overrides, then leaderboard recompute inside one transaction),
  `update_homework_answers_from_admin`, `rescore_homework_submission`,
  `apply_homework_admin_score_overrides`, `update_project_submission_from_admin`,
  `update_project_criteria_scores_from_admin` (`ProjectEvaluationScore.update_or_create`).
- Homework views `studio_courses/views/homework.py`: `homework_score`, `homework_rescore`
  (resets homework state to OPEN, then `courses/scoring.py score_homework_submissions`),
  `homework_extend_deadline`, `homework_notify_scores`, `homework_set_correct_answers`,
  `homework_clear_correct_answers`, `homework_submissions`, `homework_save_answers`,
  `homework_submission_edit`.
- Project views `studio_courses/views/projects.py`: `project_assign_reviews`
  (`courses/project_assignment.py` plus peer-review notification email),
  `project_score` (`courses/project_scoring.py score_project` plus notification email),
  `project_submissions`, `project_submission_edit`, `project_extend_deadline`.
- Complaint views `studio_courses/views/enrollment.py` and
  `views/enrollment_complaints.py`: complaints list and resolve; resolve sets
  `resolved`, `resolved_at`, `resolved_by` and does not recompute totals.
- Campaign views `studio_courses/views/campaigns.py` and `campaign_lifecycle.py`:
  campaign CRUD and the stop-registration / open-new-cohort lifecycle, backed by
  `courses/services/registration_campaigns.py`.
- Access: `@staff_required` (`views/helpers.py`) = `is_staff` plus the `site_admin` or
  `course_operator` group. The package gate is `community_base.kernel.decorators.staff_required`
  (is_staff); group checks stay a site concern.
- Not ported: datamailer operations, CloudWatch dashboards, impersonation (already in the
  package studio), deadline extension, admin submission-edit score overrides, notification
  emails, certificates (already surfaced in curriculum studio).

## Package mapping

- Homework score and rescore: `community_base.coursework.scoring.score_homework_submissions`
  with `force=True` for the donor rescore; leaderboard and statistics recompute inside the
  scoring transaction.
- Peer review administration: `review.assign_peer_reviews_for_project`,
  `review.score_project`.
- Leaderboard recompute: `leaderboard.update_leaderboard`.
- Complaint resolution: `leaderboard.resolve_leaderboard_complaint` (donor parity: no
  recompute).
- Campaign lifecycle services: `registration.stop_registration`, `registration.open_new_cohort`
  (services exist from C5.2db; studio UI out of scope here).
- Registration campaign and testimonial surfaces: testimonial management landed as
  `coursework/testimonials.py`; wrapped statistics as `coursework/wrapped.py`.

## Donor tests mirrored

`studio_courses/tests/`: `test_homework_views.py` (29), `test_studio_course_routes.py` (18),
`test_campaign_views.py` (13), `test_project_action_views.py` (9), `test_project_views.py` (6),

### Addendum: testimonial and wrapped donor-parity top-up

Donor `courses/tests/test_testimonials.py` (23 tests) and the wrapped family
`test_wrapped_statistics.py` (2), `test_wrapped_user_statistics.py` (2),
`test_wrapped_recalculation.py` (1), `test_wrapped_views.py` (5) with base
`wrapped_statistics_base.py` were not counted in the original port. They are mirrored now in
`tests/coursework/test_testimonials.py` (22 tests) and `tests/coursework/test_wrapped_extra.py`
(9 tests), bringing the package wrapped tests to 14 (5 in `tests/coursework/test_wrapped.py`
plus the 9 new ones).

Ported to `tests/coursework/test_testimonials.py`: the five placement-constraint tests (the
valid-scope test split into one item per placement, the `clean()` error parametrized over both
placements), the three homepage-read tests (donor `homepage_testimonials()` assertions ported
to the package service `published_testimonials()`, including the one-query read), plus
service-level equivalents of donor fixture intents: a course-scoped read test, a
`(position, id)` tie-break test, and the publish/unpublish/reorder management assertions the
package owns. The two portrait-key validation tests port as the six refused-key cases
parametrized plus the ordinary-key case; the donor empty-key test ports as its
validation-level meaning (an empty key is valid data).

Ported to `tests/coursework/test_wrapped_extra.py`: the donor platform-statistics and
leaderboard tests, both per-user statistics tests (Alice, Bob) with the donor base fixture
values, and the forced-recalculation idempotence test; `cohort_year` becomes `cohort_slug` per
the package model mapping. The donor view tests (5) are template/view assertions the package
does not carry; their service assertions port instead: `get_user_wrapped` returning nothing for
a user without a row (the donor no-activity path), visible-row selection and the leaderboard
read model (already in `test_wrapped.py`). The donor calculator's get-or-create short-circuit,
year-window participant selection and delete-and-recreate persistence semantics gain direct
tests (stale-until-forced, exclusion of out-of-window submissions, `replace_user_wrapped_statistics`).

Not ported, with reasons: the two seeded-homepage tests (donor reference data
`courses/homepage_testimonials.json` is a site concern), the five reviewed-file import tests
(site import machinery per the scope decision above), five of the seven portrait-resolution
tests (the package model stores the key and validates its shape; the site-side
`portrait_url` static-storage resolution they pin does not exist in the package), and the
Django admin registration test (site admin). Donor view specifics that name site URLs,
templates or share text (`twitter_text`, `cohort_identifier` links) stay with the later
adoption issues.
