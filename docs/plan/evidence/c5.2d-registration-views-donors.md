# C5.2d donor analysis: DTC registration views, routes and services

Source: `DataTalksClub/website` worktree at `ca49f1bf` (dirty worktree; this reflects
worktree state, not a committed revision). Donor app: `courses/`. Read-only analysis.

## 1. URL configuration

- Root URLconf `course_management/urls.py` mounts `path("", include("courses.urls"))`;
  `courses/urls.py` has no `app_name`, so all URL names are global.
- Registration route: `register/<slug:campaign_slug>/` ->
  `courses.views.registration.registration_campaign_view`, name `registration_campaign`.
- Route contracts file `_docs/compatibility/course-route-contracts.json` entry for it:
  `contract_kind: html`, `surface: Public courses`, `host: courses.datatalks.club`,
  `classification: preserve`, `urlconf: courses.urls`, plus `source_name`,
  `source_route_pattern`, `source_revision` provenance fields.
- Leaderboard routes (from the same contracts file, names `leaderboard`,
  `leaderboard_score_breakdown`, `leaderboard_complaint`):
  - `/<slug:course_slug>/leaderboard` and `/<slug:course_slug>/<slug:cohort_year>/leaderboard`
    -> `courses.views.course_leaderboard.leaderboard_view`.
  - `.../leaderboard/<int:enrollment_id>/` -> `leaderboard_score_breakdown_view`.
  - `.../leaderboard/<int:enrollment_id>/report` -> `leaderboard_complaint_view`.
- Canonical cohort routes use prefixed names (`cohort`, `cohort_calendar`, `cohort_homework`,
  `cohort_leaderboard`, `cohort_dashboard`, `cohort_projects`, `cohort_enrollment`,
  `cohort_module`, `cohort_unit`); legacy two-segment routes reuse the unprefixed names.
- Compatibility API surface also exists (preserve): `api_registration_campaigns`,
  `api_registration_campaign_detail`, `api_registration_campaign_registrations`
  (`/api/registration-campaigns/...`) and `api_course_leaderboard`
  (`/api/courses/<slug:course_slug>/leaderboard.yaml`).
- No route in this area requires login via decorator; gating is done inside the view.

## 2. `registration_campaign_view` behavior

`courses/views/registration.py` (215 lines), function flow:

1. `_active_registration_campaign(campaign_slug)`:
   `get_object_or_404(RegistrationCampaign, slug=campaign_slug, is_active=True)`.
2. `registration_is_gated(request)`: False for authenticated users; otherwise
   `bool(getattr(settings, "REGISTRATION_REQUIRES_ACCOUNT", True))`. Setting is defined in
   `website/settings/base.py` via `env_flag(..., default=True)`; it is the spec section 8.3
   revert lever.
3. If gated:
   - POST is redirected to `reverse("login")` with `?next=<quoted request.path>`; no
     anonymous row is ever created.
   - GET renders `courses/register.html` with `form=None`, `registration=None`,
     `registration_gate=True`.
4. Not gated:
   - `_existing_user_registration`: only when authenticated; first
     `CourseRegistration` for the campaign matching `Q(user=request.user) |
     Q(email_normalized=user.email.strip().lower())`.
   - `_registration_form`: `CourseRegistrationForm(request.POST, campaign=..., user=...)`
     on POST, otherwise unbound.
   - On POST, `_save_registration_if_valid`: if valid, `form.save()`, then
     `transaction.on_commit(partial(sync_registration_to_datamailer, registration))` and
     `transaction.on_commit(partial(send_registration_confirmation_email, registration))`.
   - On successful save only: `record_event("registration.submitted", request=request,
     user=request.user, properties={"campaign_slug", "course_slug" ("" when no course),
     "registration_id", "accepted_newsletter"})`.
   - Renders `courses/register.html` with `registration = new or existing`. There is no
     redirect after POST; the done state is rendered from the bound form
     (`_registration_done.html` shows "You are registered" when `form.is_bound`, else
     "You are already registered").
5. `campaign_course_is_open(campaign)`: current course exists AND
   (`Homework.objects.filter(course=course).exists()` OR same for `Project`).
6. `_start_course_url`: `reverse("course", kwargs=cohort_url_kwargs(current_course))`
   (kwargs `course_slug`, `cohort_year=cohort.identifier`); empty string without a course.

## 3. View context (template contract)

`_registration_context` returns exactly:

- `campaign` (RegistrationCampaign), `course` (`campaign.current_course`, may be None)
- `course_is_open` (bool), `signup_count` (int or None, see section 5)
- `form` (may be None on gated GET), `registration` (may be None)
- `marketing_html` (`mark_safe(render_markdown(campaign.marketing_markdown))`)
- `video_embed_url` (`youtube_embed_url(campaign.video_url)`)
- `start_course_url`, `country_options` (`ordered_countries()`)
- `registration_gate` (bool), `profile_identity`
  (`authenticated_registration_identity(user)` dict: `name`, `email`, `country`, `role`
  label; empty dict for anonymous), `missing_profile_fields` (tuple subset of
  `("name", "country", "role")` the account has not supplied)
- `canonical_url` is not set by the view; it comes from a site context processor using
  `core.seo.validated_canonical_url` (used by `{% canonical_link %}` in the template).

Template `courses/templates/courses/register.html` (593 lines) extends
`core/content_page.html`; blocks: `document_title` ("`{{ campaign.title }} Registration -
DataTalks.Club`"), `metadata` (canonical link), `page_styles` (inline stylesheet, no
external CSS), `header_band_class` (`registration-hero`), `header_attributes`,
`page_header` (breadcrumbs Courses / course family / current="registration", hero image,
`edition_label` or fallback "Next edition", signup count line
"`{{ signup_count }} already registered`", one of three state panels: course open with
"Start course" button via `core/_button.html`, registration open, register for next
edition), `page_content` (marketing/video section; then four exclusive states:
`_registration_done.html` when `registration`; `_registration_gate.html` when
`registration_gate` (sign-up/login card, resolves `{% url 'account_signup' %}` defensively,
`?next={{ request.path|urlencode }}`); `_registration_final_step.html` for authenticated
users (read-only `profile_identity` rows plus only the missing fields, reusing
`_registration_field.html`); full form card for anonymous users only while the gate is
off), `page_scripts` (`country_combobox.js` static plus inline submit-button
`checkValidity` sync via `data-registration-form` / `data-registration-submit` /
`data-busy-label="Registering…"` hooks). Partials: `_registration_gate.html`,
`_registration_final_step.html`, `_registration_done.html`, `_registration_consent.html`,
`_registration_field.html`. Form POST carries `{% csrf_token %}`, accessible error summary
via `{% accessibility_error_summary form %}`, combobox hooks
`data-country-combobox-input` / `data-country-combobox-panel` / `country-options-json`
(country options come from `country_options` context).

## 4. `CourseRegistrationForm` (`courses/views/registration_form.py`)

- `forms.ModelForm` on `CourseRegistration`, fields in order: `email`, `name`,
  `company_name`, `country`, `role`, `comment`, `accepted_newsletter`. Constructor pops
  `campaign` and `user` kwargs.
- `configure_registration_form_fields`: makes `name`, `company_name`, `country`, `role`,
  `comment` optional (`required = False`; only `email` and `accepted_newsletter` stay
  required); replaces the country select widget with a `TextInput` combobox
  (`autocomplete="country-name"`, placeholder "Start typing your country",
  `data-country-combobox-input`); prefixes role choices with `("", "Select role")`.
- `configure_authenticated_registration_user`: email field gets `initial = user.email`,
  `disabled = True`, help text "Using your account email."; when unbound, initial
  `name` (`user.certificate_name or user.get_full_name()`), `country`, `role`
  (`user.registration_role`).
- `clean_email`: authenticated users always use `user.email` (posted value ignored);
  normalizes `strip().lower()`; if
  `CourseRegistration.objects.filter(campaign, email_normalized).exists()` raises
  "You have already registered for this course." (duplicate rule per campaign+email).
- `clean_country`: empty allowed; otherwise `region_for_country(country)` must be
  non-empty, else "Select a valid country."
- `clean_accepted_newsletter`: must be True ("This field is required.").
- `save(commit=True)`: sets `campaign`, `course = campaign.current_course`,
  `region = region_for_country(country)`; authenticated users get
  `user = request.user` and `email = user.email`; then `registration.save()` (model save
  recomputes `email_normalized` and defaults `course` to the campaign's current course
  only when unset) and `save_registration_user_profile(user, registration)`.

Profile sync (`courses/views/registration_profile.py`, 39 lines, helper module - no view):
`registration_profile_values` maps registration to user fields
`certificate_name <- name.strip()`, `country`, `region`, `registration_role <- role`;
`update_user_profile_field` skips empty values and unchanged values, `setattr`s the rest,
returns changed field names; caller saves with `user.save(update_fields=...)`.
`registration_role_label` renders unknown stored role values verbatim via
`CourseRegistration.Role(role_value).label` with `ValueError` fallback.

## 5. Public count semantics (`courses/services/registration_counts.py`, 58 lines)

- `PublicCourseRegistrationCount` frozen dataclass with `count: int`.
- `public_course_registration_count(campaign)`:
  - `cohort = campaign.current_course`; returns `None` when unset (no cohort promoted ->
    no count rendered; every other campaign renders its live total).
  - Baseline applies only while `campaign.registration_baseline_cohort_id == cohort.id`;
    then `baseline_count = campaign.registration_baseline_count` and
    `native_start_at = campaign.registration_native_start_at`. A rotated baseline never
    carries onto a new cohort.
  - Native rows: `CourseRegistration.objects.filter(campaign=campaign, course=cohort)`,
    plus `created_at__gte=native_start_at` when a baseline applies (avoids double
    counting pre-cutover rows).
  - Result: `baseline_count + native_rows.count()`, computed live; nothing is cached or
    historized.
- Donor naming note: the donor FK is `RegistrationCampaign.current_course` (to `Cohort`)
  and `CourseRegistration.course`; the package `coursework` app already uses
  `current_cohort` / `cohort` naming for the same shape.
- Migration `courses/migrations/0002_simplify_registration_counts.py` backfills these
  plain fields from the older `baseline_plus_native` / `rows_only` slot modes.

## 6. Campaign binding service (`courses/services/registration_campaigns.py`, 234 lines)

- Module docstring rules: registration happens only on this site; a cohort binds to a
  campaign through `RegistrationCampaign.current_course` ("register for this edition",
  cleared by CMP when registrations close) or `Cohort.registration_url`
  (`https://courses.datatalks.club/register/<campaign-slug>/`, "this course registers
  here", outlives current_course). Nothing is derived: an unparseable URL or unknown slug
  resolves to no registration at all (e.g. finished `mlops-zoomcamp-2025` stays silent).
- `campaign_slug_in_registration_url(url)`: regex
  `^https?://[^/]+/register/(?P<slug>[a-z0-9](?:[a-z0-9-]*[a-z0-9])?)/?$`; host
  unconstrained; empty string on no match.
- `active_campaign_for_cohort(cohort)`: first (lowest `id`) active campaign with
  `current_course=cohort`.
- `next_edition_campaign_for_cohort(cohort)`: active campaign named by
  `cohort.registration_url` slug, excluding one that currently promotes this cohort
  (that case belongs to `active_campaign_for_cohort`).
- `FamilyRegistration` frozen dataclass (`campaign`, `cohort`, truthy iff campaign set);
  `family_registration(family)`: editions =
  `family.cohorts.filter(visible=True).order_by("-year", "-id")`; first pass returns
  `FamilyRegistration(campaign, cohort)` for the first edition with an active campaign;
  second pass returns `FamilyRegistration(campaign)` (no cohort named) for a
  waiting-list campaign; else empty.
- State machine writes (audited, `using` parameter, row re-fetch inside
  `transaction.atomic`):
  - `stop_registration(campaign, *, actor_ref, actor_id=None, context=None,
    using="default")`: `current_course` must be set else
    `RegistrationCampaignStateError`; sets it to None, saves
    `update_fields=("current_course", "updated_at")`, audit action
    `courses.registration_campaign.registration_stopped` with
    `changes={"current_course_id": {before, None}}` and metadata campaign_id +
    `previous_cohort_slug`.
  - `open_new_cohort(campaign, cohort, *, actor_ref, ...)`: only valid from the
    "future/none" state (must stop first), cohort must have a pk; audit action
    `courses.registration_campaign.cohort_opened`, metadata campaign_id +
    `cohort_slug`.
  - Audit plumbing: `validate_actor_ref`, `ServiceContext.from_current`,
    `AuditWriteContext.from_service_context`, `record_audit_event`, `core.models.AuditEvent`.

## 7. `courses/registration.py` helpers (332 lines)

- Countries: parses `courses/countries.txt` INI-style (`[Top Countries]` section plus
  region sections; `#` comments). Builds `COUNTRIES_BY_REGION`, `TOP_COUNTRIES`,
  `COUNTRY_REGION` (country -> region), `ordered_countries()` (top countries first, rest
  alphabetical) and `COUNTRY_CHOICES`. `region_for_country(country)` returns `""` for
  unknown.
- `render_markdown(text)`: mistune with `escape=False` (author HTML passes through the
  sanitizer), table plugin rendering scrollable semantic tables, Mermaid fences rendered
  as escaped `<div class="mermaid">`, headings clamped to level >= 2; then
  `bleach.clean` with `ALLOWED_MARKDOWN_TAGS` (large allowlist incl. `img`, `details`),
  attribute allowlist function (code `class` limited to `language-*` tokens; `img src`
  limited to absolute http(s) or the managed `/course-assets/lessons/<uuid>/<sha256>/...`
  prefix; protocols http/https/mailto); finally drops sourceless `<img>` elements.
  `markdown_has_mermaid(html)` checks for the mermaid div.
- `youtube_embed_url(url)`: accepts `youtube.com/watch?v=` and `youtu.be/<id>` forms,
  returns `https://www.youtube.com/embed/<id>`; any other non-empty URL is returned
  unchanged.

## 8. Side effects and observability

- `record_event(name, *, request=None, user=None, distinct_id=None, properties=None)` in
  `course_management/observability/events.py` builds an `AppEvent` with a resolved
  distinct id and request-enriched properties and fans out to configured backends, each
  wrapped in try/except with `logger.exception("observability backend failed ...")`.
  Registration uses exactly one event: `registration.submitted` (properties above).
- Datamailer sync (`sync_registration_to_datamailer`): no-op when
  `DatamailerConfig.from_settings()` is None; builds a contact payload (subscribed,
  verified, `email_validation.status="externally_validated"`, tags from course) and a
  recipient-list member payload (list key `registration_list_key(registration)`, list
  name "`<course title or campaign title> registrants`", source object key
  `registration:<pk>`, metadata registration_id / campaign_slug / course_slug /
  registered_at isoformat), enqueued as one outbox event
  `recipient_list.member_upsert` with an idempotency key
  `recipient-list.member-upsert:<list_key>:<source_object_key>:<pk>:<ClassName>` and an
  ordering key. Removal path: `remove_registration_from_datamailer`.
- Confirmation email (`send_registration_confirmation_email`): payload
  `registration_confirmation_payload`; subject "Registration confirmed:
  `{{ campaign.title }}`"; URLs resolved via `public_route_url` for
  `registration_campaign`, `course`, `account_settings`; metadata includes
  `source: "course-management-platform"`, `event: "course_registration"`, preference key
  `email_course_updates`. Returns None when the payload is None.
- `registration_email(registration)` = `(email_normalized or email).strip().lower()`.

## 9. Model facts the views rely on

- `RegistrationCampaign`: `slug` unique, `title`, `edition_label`, `current_course` FK
  (SET_NULL, related_name `registration_campaigns`), `is_active` default True,
  baseline triple (`registration_baseline_cohort` FK related_name `+`,
  `registration_baseline_count` PositiveIntegerField default/db_default 0,
  `registration_native_start_at` DateTimeField null), `marketing_markdown`,
  `meta_description`, `hero_image_url`, `video_url` (URLValidator), timestamps; ordering
  `["title", "slug"]`.
- `CourseRegistration`: `campaign` FK CASCADE; `course` FK SET_NULL null;
  `user` FK SET_NULL null related `course_registrations`; `email`, `email_normalized`
  (editable=False), `name`, `company_name`, `country`, `region`, `role` (9-value
  `Role` TextChoices: data_engineer, data_scientist, data_analyst, ml_engineer,
  software_engineer_backend, software_engineer_other, student_stem, student_non_stem,
  other), `comment`, `accepted_newsletter` default False, timestamps;
  `unique_together ["campaign", "email_normalized"]`; ordering `["-created_at"]`.
  `save()` normalizes the email and defaults `course` to the campaign's current course
  when unset. CMP import sets `email_normalized` explicitly because `bulk_create` skips
  `save()`.
- Consumers of the same models: `course_list_user_state` /
  `member_home` (`registered_campaign_ids` by `email_normalized`, `my_cohorts` unions
  `Q(user=user) | Q(email_normalized=...)`), `course_page_context`
  (`family_registration`), studio campaign metrics and registration list, accounts
  identity inventory (`courses.CourseRegistration.user` reparent spec), signup form role
  choices reuse.

## 10. Site coupling vs portable core

- Site-specific (must stay behind adapters/hooks in the package):
  `course_management.datamailer` sync + payloads, `course_management.observability
  record_event`, `settings.REGISTRATION_REQUIRES_ACCOUNT`, `reverse("login")` /
  `account_signup` / `home` / `course` route names, `core.seo` canonical URL context
  processor, `core/content_page.html` base template and design-system partials,
  `country_combobox.js` static asset, `core.audit`/`core.services` audit context,
  `accounts` profile fields (`certificate_name`, `country`, `region`,
  `registration_role`), `courses.views.url_utils` cohort URL helpers.
- Portable as-is: form definition and validation rules, duplicate-email rule,
  `CourseRegistration` model save semantics, public count service, campaign binding
  service (minus audit backend), campaign state machine rules, countries config parsing,
  region derivation, markdown sanitizer policy, youtube embed parsing, gated-view
  control flow.

## 11. Leaderboard donor notes (secondary, for the same issue)

- `courses/leaderboard.py` (84 lines): `update_leaderboard(course)` recomputes
  `Enrollment.total_score` = sum of `Submission.total_score` grouped by enrollment for
  the course's homeworks + sum of `ProjectSubmission.total_score` grouped by enrollment
  for the course's projects excluding `volunteer_review_only=True`; ranks by
  `(-total_score, enrollment.id)` into `position_on_leaderboard` starting at 1;
  `bulk_update(["total_score", "position_on_leaderboard"])`; invalidates cache keys
  `leaderboard:{id}`, `leaderboard_data:{id}`, `leaderboard_yaml:{id}` and increments
  `leaderboard_cache_version:{id}` (set None timeout); logs start/finish.
  Callers: project scoring (`project_scoring.py` line 110), `enrollment_flags`
  service, admin action `update_leaderboard_admin`.
- Enrollment leaderboard fields: `display_name` (CharField 255, verbose "Leaderboard
  name", blank; `save()` defaults it to `courses.random_names.generate_random_name()`
  = "`<adjective> <famous person>`" from bundled word lists), `display_on_leaderboard`
  BooleanField default True, `position_on_leaderboard` IntegerField, `total_score`
  IntegerField default 0. `LeaderboardComplaint` model (issue_type choices, reporter,
  resolved/resolved_by/resolved_at, description) with admin.
- View layer: `course_leaderboard_data.py` caches `leaderboard:{course.id}`, hides the
  current student when `not enrollment.display_on_leaderboard`, and cache deletion bumps
  the version key. Spec `_docs/specs/04-courses-and-cohorts.md` normative lines:
  baseline is "at most, a fixed historical figure recorded" (section on campaign count
  semantics quoted in section 5 above) and "Existing leaderboard name/visibility,
  certificate name, score rollups, learning-in-public controls, and timestamps remain
  cohort-specific" (Target model), plus "Preserved learner behavior": cohort leaderboard,
  breakdown, visibility preferences, complaints, graduate export, certificate updates.
- Score sources: `Submission.total_score = questions_score + learning_in_public_score +
  faq_score` (`homework_score_calculation.update_score`); `ProjectSubmission` carries
  `project_score`, `project_faq_score`, `project_learning_in_public_score`,
  `peer_review_score`, `peer_review_learning_in_public_score`, rolled into
  `total_score` and a `passed` flag (C5.2c work already covers this).
