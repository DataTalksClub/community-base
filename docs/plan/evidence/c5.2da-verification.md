# C5.2da leaderboard rollup, preferences and complaints verification

Verified: 2026-09-08

## Delivered capability

- `coursework/leaderboard.py` write side: `update_leaderboard(cohort)` full recompute of
  `Enrollment.total_score` and `position_on_leaderboard` (integer sums of homework
  submissions and non-volunteer project submissions, `(-total_score, enrollment id)`
  ranking, one `bulk_update`, cache invalidation).
- Read side in the same module: visibility filter, `Coalesce` ordering, pagination,
  serialization with `passed_projects` medals and the current-student staleness rebuild.
- `coursework/enrollment_flags.py` `set_learning_in_public_disabled`: zeroes learning-in-public
  scores, recomputes affected totals and refreshes the leaderboard in one transaction.
- `coursework/random_names.py` `ensure_display_name` with the configurable
  `COURSEWORK_DISPLAY_NAME_GENERATOR` hook; complaint services `file_leaderboard_complaint`
  and `resolve_leaderboard_complaint`.
- `coursework/scoring.py` batch scorer `score_homework_submissions` (donor
  `courses/scoring.py`): guard fail-closed semantics, transactional bulk scoring, and the
  leaderboard refresh plus `first_homework_scored` and statistics updates inside
  `_mark_homework_scored`.
- `COURSEWORK_PROJECT_LEADERBOARD_UPDATER` defaults to the package updater and stays
  site-overridable; the `Cohort` duplicated field definitions are removed.

## Deviations recorded

- Display names are filled by the `ensure_enrollment`/`ensure_display_name` services instead
  of overriding `Enrollment.save()`: the shared model keeps no hidden write side effect, and
  sites opt into name generation through the same call sites the donor reaches from its
  `save()` override.
- `ensure_display_name` lives in `coursework/random_names.py` rather than inline in the
  leaderboard module, matching the donor file layout; the donor word lists stay site data,
  so the package default generator is a plain fallback.
