# C3.1c account service donor behavior matrix

Captured from the AISL donor and the DTC member-profile specification on 2026-09-05. C3.1c adds
package capability without removing donor code. The copied-test count and donor-equivalence gates
therefore remain deferred to C3.7.

No donor test is copied byte for byte. Package tests are adapted around portable contracts and use
the durable mail outbox. The table records what later extraction may replace and what must remain a
site integration.

| Area | Donor behavior retained or adapted | Package evidence | Deferred or site-owned behavior |
|---|---|---|---|
| Verification | Configurable positive unverified TTL; database-clock resend claim with cooldown and token-safe failure release | `tests/accounts/test_auth.py`, `tests/accounts/test_services.py` | Purge and reminder schedules, site copy, analytics and production delivery checks |
| Email resolution | Normalized, case-insensitive active primary lookup; active alias fallback; primary precedence | `tests/accounts/test_auth.py`, `tests/accounts/test_services.py` | DTC identity quarantine and course continuity |
| Alias operations | Validated normalized aliases, single ownership, idempotent same-owner add and safe removal | `tests/accounts/test_services.py` | Studio forms, permissions and audit presentation move in C3.1e; Stripe relay ownership stays with the site adapter |
| Email change | Password check for password users, address collision checks, same-address cooldown, one active request, 24-hour single-use confirmation, confirmation-time recheck, allauth synchronization, former-address alias and old-address notice | `tests/accounts/test_services.py` | Tier/newsletter eligibility and account-page presentation are not domain-service rules; the self-service surface moves in C3.1d |
| Action mail security | Verification, password-reset and email-change bearer URLs are resolved only in the worker; durable delivery context contains non-secret identifiers and produces deterministic retry payloads | `tests/accounts/test_auth.py`, `tests/accounts/test_services.py`, `tests/mail/test_jobs.py` | Site templates, branding and public base URL configuration |
| Merge | Atomic locking, self/staff safeguards, dry run rollback, shared scalar and preference reconciliation, profile/groups/permissions transfer, allauth/social/mail/note/import transfer, API-key revocation, alias creation and secondary credential scrubbing | `tests/accounts/test_services.py` | Tier/subscription conflicts and site-model relation strategies use `ACCOUNT_MERGE_HOOK`; staff UI and audit presentation move in C3.1e |
| Privacy export | Portable account, profile, alias, social, API-key metadata, note and mail metadata export; credential material excluded; salted audit identity | `tests/accounts/test_services.py` | Learning, event, CRM, payment, Slack, Calendly, sprint, comment and book-club sections use `ACCOUNT_PRIVACY_EXPORT_HOOK` |
| Privacy deletion | Idempotent request, site blocker, session invalidation, mail anonymization, cascade deletion and retained audit summary | `tests/accounts/test_services.py` | Subscription blocking is supplied by `ACCOUNT_DELETION_BLOCKER`; site row erasure uses `ACCOUNT_BEFORE_DELETE_HOOK`; staff/Slack notices stay site-owned |
| Free welcome | Durable, idempotent package mail purpose | `tests/accounts/test_services.py` | Site template wording and campaign scheduling |
| Timezone | IANA validation, deterministic offset-sorted options, aware/naive datetime formatting and UTC fallback | `tests/accounts/test_services.py` | Account links and email prose are presentation concerns |
| Import users | Adapter registry, BOM-safe CSV, alias-aware reconciliation, unusable passwords, fill-empty identity updates, earliest non-manual source retention, source-scoped metadata, normalized tag union, conflict records, audit counters, optional durable welcome and rollback-only dry run | `tests/accounts/test_services.py` | Course aggregation, Slack workspace access, Stripe subscription/tier mutation, site commands, admin and queue pacing belong to adapters or C3.1e |
| Mail preferences | Default resolver suppresses global unsubscribe, permanent bounce and explicit category opt-out while leaving unknown user-like objects allowed | `tests/accounts/test_services.py` | Site preference categories and management surfaces move through adoption or C3.1d |

## Extraction notes

- AISL sources inspected: `accounts/services/`, account service tests, API integrations and Studio
  merge/import operations.
- DTC source inspected: `_docs/specs/01-platform-architecture.md` member-profile sections.
- Tier, Stripe and Slack workspace behavior is deliberately absent from package service tests.
- Package extension hooks keep cross-domain work explicit without importing site applications.
- Initial kept-label migrations remain provisional. C3.1c must not be tagged or released.
