# C3.1b authentication donor differences

The package uses the AISL authentication policy where the donors differ, as required by C3.1b.

| Setting or behavior | Package and AISL | DTC | Adoption note |
|---|---|---|---|
| Plain signup | Open email signup | Closed by `ClosedAccountAdapter` | DTC may override the account adapter during adoption. |
| Signup fields | Email only in allauth | Email and two password fields | Package-owned registration collects one password and validates it. |
| OAuth providers | Google, GitHub and Slack | GitHub only | Sites configure provider credentials independently. |
| Social auto-signup | Enabled | Adapter-controlled | Package follows AISL. |
| Verified-email matching | Allauth email authentication plus alias adapter | DTC reconciliation and quarantine | DTC conflict quarantine stays site-owned. The package acts only on one verified provider email. |
| Slack signup | Existing or aliased accounts only | Not configured | An unmatched Slack identity cannot create an account. |
| Authentication backend | Django and allauth backends | DTC durable backend | DTC retains its backend until its identity adoption issue. |

The package excludes AISL tier, Stripe, Slack workspace probing, GA analytics and welcome-email
side effects. It excludes DTC course identity reconciliation, quarantine, observability and closed
registration. Those behaviors cross site-owned domain boundaries and remain adoption concerns.
