## Model decisions

- Keep AISL's automatic integer `Event` primary key because the package keeps the `events` Django
  label and C4.3 must replace AISL's migration history.
- Add a nullable, unique, positive `Event.public_id` for DTC's stable numeric route identity.
- Allocate new public IDs through a locked singleton sequence. Never derive, reuse or renumber
  them.
- Keep the cosmetic slug separate from both identities. DTC UUID, date/title and renamed paths
  become explicit `EventAlias` rows during adoption.
- Keep one package `Host` model. `kind` distinguishes host, instructor and speaker, while
  `external_ref` lets a site resolve its canonical person profile.
- Keep ordered `EventHost` assignments. Remove AISL's direct `content.Instructor` relationship;
  importer code maps those people into `Host(kind="instructor")`.
- Keep `EventSeries` and its weekly or cadence-free schedule metadata. Occurrences use a nullable
  `event_series` relation and a stable one-based position.
- Keep DTC Q&A sessions and historical registration aggregates outside this package app, as the
  Phase 4 adoption plan requires.

## Service boundaries

- Call `community_base.kernel.access.can_access` for registration eligibility.
- Resolve host profile URLs through `HOST_PROFILE_RESOLVER`.
- Publish, cancel and reschedule through atomic services that emit package lifecycle events only
  after commit.
- Leave mail, registration lifecycle, Zoom, ICS, banners, writeups, jobs and HTTP surfaces to the
  later C4.1 slices.

The initial `events` migration remains provisional and untagged. Exact AISL model state, literal
`replaces` names, PostgreSQL rehearsal and development-copy evidence remain C4.3 work.
