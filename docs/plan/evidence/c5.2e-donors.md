## Scope

C5.2a moved the models (including `Testimonial`, `WrappedStatistics`, `UserWrappedStatistics`).
C5.2b/C5.2c/C5.2da/db/dc moved the services the studio actions call: homework scoring,
project and peer review scoring, leaderboard rollup, complaint filing and resolution,
registration campaign state machine, learner views, member APIs and `issue_certificate`.
This issue adds the staff surfaces: the `studio_courses` operations, the testimonial
management surface and the Wrapped statistics read/recalculate surfaces.

## Step 1 surfaces: studio operations

### Cohort list and cohort admin

- `course_list`: every `Cohort` ordered `(finished, -id)`, no pagination.
- `course_admin` (`course_admin_context`): homeworks annotated `Count("submission")`, ordered
  `due_date`, each carrying action flags `can_score` (state in OPEN, CLOSED),
  `can_notify_scores` (state SCORED) and `can_extend_deadline` (state OPEN); projects annotated
  `Count("projectsubmission")` with `needs_review_assignment` (state COLLECTING_SUBMISSIONS),
  `needs_scoring` (state PEER_REVIEWING) and `can_extend_deadline` from
  `project_extension_plan`; support metrics (`disabled_lip`, `zero_score`,
  `hidden_leaderboard`, `open_complaints` counts over the cohort's enrollments);
  registration metrics per campaign promoting the cohort (`registration_campaign_metrics`:
  total, `count_by` role/country/region); `total_enrollments`; `EXTENSION_OPTIONS` for the
  extend-deadline dropdowns.

### Homework and question management

`studio_courses/views/homework.py`; all POST-only except the submissions list, every action
redirecting through `redirect_after_action` (honours a safe `next` POST field, else the cohort
admin page).

- `homework_score`: `score_homework_submissions(homework.id)`; OK -> success message, FAIL ->
  warning message. The package service is C5.2b/C5.2da's `coursework/scoring.py`.
- `homework_rescore`: rejects a homework that is not SCORED ("Use Score submissions instead");
  otherwise sets state back to OPEN and runs the same scoring service.
- `homework_extend_deadline`: only OPEN homework; `extend_deadlines` validates `days` against
  `ALLOWED_EXTENSION_DAYS` {1, 3, 7} and pushes `due_date` forward.
- `homework_notify_scores`: requires SCORED, then `send_homework_score_notification`
  (datamailer email). Site integration territory: the package exposes no equivalent action;
  sites wire score notifications to the coursework hooks and Relay.
- `homework_set_correct_answers`: `fill_correct_answers` sets each question's `correct_answer`
  to its most popular non-empty `Answer.answer_text`, skipping questions that already carry a
  valid choice index set (`has_invalid_correct_answer_indices` guards out-of-range indices).
- `homework_clear_correct_answers`: `Question.objects.update(correct_answer="")`, count
  reported in the message.
- `homework_save_answers`: per question `correct_answer_<id>` (choice questions join the
  posted index list with commas) and `answer_type_<id>` (empty string becomes NULL), saved
  with `update_fields=["correct_answer", "answer_type"]`.

### Submissions and rescoring

- `homework_submissions`: `Submission` rows for the homework, `select_related(student,
  enrollment)`, newest first, searched on `student__email__icontains` or
  `student__username__icontains`, paginated 25 per page with an elided page range; the
  homework's questions ride along for the correct-answers editor on the same page.
- `homework_submission_edit` (GET + POST): form fields `answer_<question_id>` per question,
  `learning_in_public_links` (textarea, split on lines), `faq_contribution_url` and
  `faq_score` (falls back to the stored score when empty). POST runs
  `update_homework_submission_from_admin` in one transaction: `update_or_create` one `Answer`
  per question, replace the link list, re-run the per-submission scoring (`update_score`),
  then apply the admin overrides (`faq_score`, recomputed total), and finally call
  `update_leaderboard(course)` only when the total changed.

### Projects, criteria and peer review administration

`studio_courses/views/projects.py`:

- `project_assign_reviews`: `assign_peer_reviews_for_project`; OK additionally sends the peer
  review assignment notification (datamailer; site-side in the package).
- `project_score`: `score_project`; notifications likewise site-side.
- `project_extend_deadline`: `project_extension_plan` returns both dates while collecting
  submissions ("both deadlines") and only `peer_review_due_date` during peer review; closed
  and completed projects cannot be extended.
- `project_submissions`: action flags per submission (`apply_project_action_flags`), paginated
  context. `project_submission_edit`: per-criteria `criteria_score_<id>` integer fields,
  `project_faq_score`, `project_learning_in_public_score`, `peer_review_score`,
  `peer_review_learning_in_public_score`, `reviewed_enough_peers`, `passed`;
  `update_project_submission_from_admin` rewrites the `ProjectEvaluationScore` rows per
  criterion, recomputes `total_score` from the five components and saves.

### Leaderboard recompute, complaints, enrollments and certificates

- Leaderboard recompute happens through the actions above (scoring, admin edits); the donor
  has no standalone recompute button in Studio Courses. `update_leaderboard` is C5.2da's
  package service.
- `leaderboard_complaints` page (`enrollment_complaints.py`): enrollments with
  `total_complaints > 0` annotated open/total counts, ordered `-open_complaints,
  -total_complaints, position_on_leaderboard`, complaints grouped per enrollment and ordered
  `(resolved, -created_at)`; header counts open/total.
- `leaderboard_complaint_resolve` (POST): sets `resolved`, `resolved_at`, `resolved_by` — the
  package's `resolve_leaderboard_complaint` service (C5.2da).
- `enrollments` list: search plus status filter with per-status counts (`view_models.py`
  `enrollment_list_data`), paginated 25.
- `enrollment_edit`: shows the enrollment's homework and project submissions with
  learning-in-public totals; POST action `toggle_learning_in_public` flips
  `disable_learning_in_public` through `set_learning_in_public_disabled` (C5.2da service,
  which zeroes the affected score columns and recomputes the leaderboard).
- Certificates: no Studio Courses surface in the donor. Certificate ingestion is the operator
  API (`api/views/enrollment_certificate_updates.py`), already mapped by C5.2dc to
  `coursework/certificates.py` `issue_certificate`. The package Studio enrollment page gains
  an issue-certificate action over that service; DTC's Django admin does the same job there.

### Registration campaigns

- `campaign_create` / `campaign_edit` (`RegistrationCampaignForm`): editable fields title,
  slug, `edition_label`, `is_active`, `hero_image_url`, `video_url`, `meta_description`,
  `marketing_markdown`; `current_course` is disabled on edit — the lifecycle actions below are
  its only writers for an existing campaign.
- `campaign_action` POST dispatch (`campaign_lifecycle.py`): `stop_registration` and
  `open_new_cohort` (with an `OpenNewCohortForm` cohort choice) call the C5.2db package
  services; both re-render the edit page with success or error messages; the donor passes
  `actor_ref`/`actor_id` audit arguments, which the package services take as site-side
  concern (the studio layer writes the audit through `STUDIO_AUDIT_WRITER`).
- `campaign_registrations`: paginated `CourseRegistration` rows with per-role/country/region
  `count_by` breakdowns (`campaign_registration_list.py`).
- The datamailer views (`campaign_datamailer.py`, `datamailer*.py`, `observability.py`:
  Cloudwatch dashboard) are site integration surfaces (email/observability transports); they
  do not move into the package.

## Step 2 surface: testimonial management

- `courses/admin/testimonial.py`: Django admin CRUD as the editing surface — list display
  `(name, placement, course, position, published)`, filters placement/published/course, search
  over name/attribution/quote, ordering `(placement, position, id)`, fieldsets grouping
  placement, person and quote fields with the optional transition fields collapsed.
  `Testimonial.clean` (model, moved in C5.2a) reports the placement scope constraint.
- `courses/services/testimonials.py`: `import_homepage_testimonials` replays a reviewed JSON
  set keyed on `source_url` (created/updated report, replay writes nothing, editor rows
  untouched) and `homepage_testimonials` reads published homepage rows ordered by position.
  The read side is the public homepage band; the import service is an ingestion tool for the
  reviewed file, which stays a site concern (the file is site data), while the management
  surface (create/edit/publish/order/delete) is what moves to the package Studio.

## Step 3 surface: Wrapped statistics read/recalculate

- Models `WrappedStatistics` and `UserWrappedStatistics` are C5.2a's; nothing recomputes them
  in the package yet.
- Calculator (`courses/wrapped_statistics/calculator.py`): `calculate_wrapped_statistics(year,
  force=False)` — get-or-create the year row, skip unless `force` or newly created, then in
  `calculate_wrapped_statistics_body` build the activity context and persist platform
  statistics and per-user statistics.
- Activity (`activity.py`): the year window `[Jan 1, Dec 31 23:59:59]` aware; homework and
  project submissions in the window; students with activity as the union of both student
  sets; enrollments from the submissions' enrollment ids; distinct courses from those
  enrollments; peer review counts per reviewer in the window.
- Persistence (`persistence.py`): platform row — `total_participants`,
  `total_enrollments`, `total_hours` (`wrapped_total_hours`, each time component capped at
  100 h, rounded to 0.1), `total_certificates` (enrollments with a non-empty
  `certificate_url`), `total_points` (sum of enrollment totals), `course_stats` (per cohort
  enrollment counts, most popular first) and `leaderboard` (top-100 by summed
  `enrollment.total_score` with rank, display name, total and student id). User rows —
  delete-and-recreate all `UserWrappedStatistics` for the year (bulk, batch 500) with
  totals, homework/project/peer-review counts, learning-in-public and FAQ counts,
  certificates earned, per-cohort course records (title/score/slugs/enrollment id), rank from
  the leaderboard data and the first enrollment's `display_name` (empty rather than the
  username when the student has no enrollment).
- Read/recalculate surfaces: `courses/admin/wrapped.py` lists years with the platform
  columns and a `Recalculate statistics` admin action calling the calculator with
  `force=True`; the learner pages (`courses/views/wrapped.py`) render the public year page
  (only when `is_visible`) and the per-member page (owner or staff, 404 otherwise, no
  activity renders an empty state). The Wrapped page context adds canonical cohort and
  leaderboard links (`wrapped_context.py`).

## Mapping to package conventions

- Studio shell: `coursework/studio_views.py`, `studio_forms.py`, `studio_urls.py`,
  `studio_registration.py` following `curriculum/studio_views.py` and
  `events/studio_views.py`; `@staff_required` from `community_base.kernel.decorators`;
  pagination through `community_base.studio.utils.studio_pagination_context` (25 per page,
  the donor's page size); audit writes through `community_base.studio.audit.hooks` the way
  the curriculum studio writes them; templates under
  `community_base/coursework/templates/community_base/coursework/studio/` extending
  `community_base/studio/base.html`.
- Studio section: slug `coursework`, registered from `CourseworkConfig.ready()`. The donor's
  route identities stay with each site; the package fixes the `coursework_studio_*` names.
- Services first: actions call the existing package services —
  `scoring.score_homework_submissions`, `leaderboard.update_leaderboard`,
  `review.assign_peer_reviews_for_project`, `review.score_project`,
  `leaderboard.resolve_leaderboard_complaint`, `leaderboard.set_enrollment_preference`
  (learning-in-public toggle maps to the enrollment flag service),
  `certificates.issue_certificate`, `registration.stop_registration`/`open_new_cohort`.
  New package services for behavior that only existed inline in studio views:
  `update_homework_submission_from_admin`, `fill_correct_answers`,
  `clear_correct_answers`, `extend_deadlines` (with the donor's 1/3/7-day options), the
  project submission admin override, and the Wrapped calculator port.
- Identity delta: the package `User` has no `username` (email is the identifier); submission
  and enrollment searches match on `student__email` and `enrollment__display_name` instead of
  the donor's email/username pair.
- Campaign form delta: the package campaign model carries `current_cohort` (donor
  `current_course`); the edit form disables that field for existing campaigns exactly like
  the donor, and the lifecycle actions remain its only writers.
- Stays a site concern: datamailer and score-notification transports (hooks plus Relay),
  the Cloudwatch dashboard and datamailer outbox pages, impersonation, the reviewed
  homepage-testimonials JSON import (site data), Wrapped canonical link helpers tied to the
  donor urlconf, message-tag styling and verbatim copy.

## Split note

The donor surface is one issue's scope but two to three pull requests of code and tests.
C5.2e is split: C5.2ea (cohort admin, homework and question management, submissions and
rescoring), C5.2eb (projects, criteria, peer review administration, leaderboard recompute,
complaint resolution, certificate management, registration campaigns) and C5.2ec
(testimonial management, Wrapped statistics read/recalculate). Each sub-issue references the
sections above.
