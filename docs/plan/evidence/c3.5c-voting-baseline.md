## Stable behavior

- `Poll`, `PollOption` and `PollVote` use UUID poll and option identifiers.
- Members toggle one vote per option, up to `max_votes_per_user` options per poll.
- Closed and expired polls reject writes. Open results sort options by vote count.
- Members can propose options only when the poll permits proposals.
- The server derives the vote and proposal owner from the authenticated request.
- Poll visibility and writes depend on `required_level`.
- Account privacy exports include a member's poll votes and proposals.
- Opening or reopening a poll can emit a notification without coupling voting to a site domain.

## Package adaptation

The split plan calls the donor a generic-target app, but the donor has no generic foreign key and
DTC has no matching poll application. The reusable target is the package-owned `PollOption`.
`community_base.kernel.access.can_access` replaces AISL's tier lookup and lets each site supply its
own access policy without changing the voting schema. Signals replace the donor admin's direct
notification import.

The package keeps the `voting` Django label and a provisional initial migration. C3.7 will verify
the exact donor migration replacement before any tag or release includes it.
