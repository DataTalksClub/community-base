# C4.2 events capability checkpoint

Verified: 2026-09-07

## Installed capabilities

The package test project installs `community_base.events` together with the kernel, accounts,
questionnaires, onboarding, community, notifications, comments, voting, API, config, jobs, mail,
studio and content sync apps. No package module in this group imports an AISL or DTC site app.

The checkpoint proves package-local events behavior across the four C4.1 issues:

- models and domain services: events, series, hosts, aliases, public identity, lifecycle
  transitions and access checks (`community_base.events.models`, `services`);
- registration: member, series with occurrence fan-out and opt-outs, accountless signup with
  verification, expiry, attendance and feedback ownership (`registration`,
  `anonymous_registration`, `reminders`);
- integrations: RFC 5545 calendar output, configuration-backed Zoom client with bounded
  failures, optional banner, write-up and recording hooks, and durable integration jobs with an
  ambiguity-safe provider mutation fence (`integrations`, `jobs`, `integration_jobs`);
- surfaces: public list, detail, registration, verification, feedback and calendar routes in
  both URL styles, Studio operations with audit hooks, and session-authenticated APIs
  (`views`, `studio_views`, `api_views`, templates under `community_base/events/templates/`).
