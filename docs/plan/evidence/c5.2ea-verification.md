# C5.2ea coursework Studio homework and submissions verification

Verified: 2026-09-08

## Delivered capability

- Studio section `coursework` registered from `CourseworkConfig.ready()`; routes mounted by
  sites under their Studio prefix, names `coursework_studio_*`.
- `studio_views.py`: cohort list and cohort admin page (homework rows with submission counts
  and the `can_score` / `can_extend_deadline` flags, support metrics over enrollments and
  open complaints), homework actions (score, rescore, deadline extension, save answers,
  fill and clear correct answers), the homework submissions page with search and pagination,
  and the submission edit page.
- `studio_services.py`: `update_homework_submission_from_admin` (answer upserts, link
  replacement, scoring pass, FAQ-score override, leaderboard refresh only on total change),
  `fill_correct_answers` / `clear_correct_answers` with the invalid-choice-key guard,
  `extend_deadlines` with the donor's 1/3/7-day options, `save_correct_answers_from_admin`,
  `cohort_homework_rows`, `cohort_support_metrics`, `homework_submissions_queryset`.
- `studio_forms.py`: `HomeworkSubmissionEditForm` with the donor field names
  (`answer_<question_id>`, `learning_in_public_links`, `faq_contribution_url`, `faq_score`)
  and the FAQ-score fallback to the stored value.
- Studio templates under `community_base/coursework/templates/community_base/coursework/studio/`,
  extending `community_base/studio/base.html`; audit writes through `STUDIO_AUDIT_WRITER`.

## Deviations recorded

- Submission search matches the student email or the enrollment display name; the donor
  matched email or username and the shared `accounts.User` has no username.
- The donor's `homework_notify_scores` action has no package equivalent: score notifications
  are datamailer emails and stay site-side (hooks plus Relay at D5.1/D5.2).
- Project and campaign blocks on the donor admin page arrive with C5.2eb; the C5.2ea admin
  page shows the homework and support-metric blocks.
- The package question model keeps answer types as module-level choices, so the submissions
  template receives them from the view instead of reading `question.ANSWER_TYPES` as the
  donor template does.
