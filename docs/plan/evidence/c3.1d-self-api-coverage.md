# C3.1d account page and self API coverage

Captured from the AISL account surfaces and the DTC member-profile version 1 contract on
2026-09-05. The package implements member-owned behavior locally without changing either donor.

## Package routes

| Method and path | Contract |
|---|---|
| `GET /accounts/account/` | Private package template for account, profile, preferences, password and privacy actions |
| `GET /api/v1/me` | Signed-in account identity and member-controlled settings |
| `PATCH /api/v1/me` | Allowlisted names, email preferences, timezone, theme and append-only card dismissal |
| `GET /api/v1/me/profile` | Private profile fields, required/missing fields, completion state and strong revision ETag |
| `PATCH /api/v1/me/profile` | CSRF-protected allowlisted update requiring a strong `If-Match`; stale writes return `409` |
| `POST /api/v1/me/password` | Current-password check where applicable, configured password validation and session preservation |
| `GET /api/v1/me/data-export` | Portable attachment from the privacy service with a retained export audit |
| `POST /api/v1/me/deletion-request` | Idempotent member-owned privacy request |

All JSON routes register through `community_base.api.registry`. Self routes explicitly select
session authentication, retain Django CSRF enforcement for mutations, return private no-store
responses and appear in the generated OpenAPI document.

## Profile contract

- GET does not create an empty row. A missing profile is revision zero and PATCH creates it.
- Country and free text are normalized before model validation. Choice and URL validation comes
  from the shared model.
- Completion version 1 requires a verified email and every required profile field.
- A member PATCH confirms the resulting revision. First completion records `completed_at`.
- Ordinary valid edits retain completion and its original completion time.
- A completed profile cannot clear a required value.
- Free text is returned only to its owner and is not copied into error details or ordinary logs.

## Adapted and site-owned behavior

`tests/accounts/test_self_api.py` adapts owner authentication, CSRF, allowlisting, validation,
completion, stale-write, password, preference, privacy and private-template behavior. API registry
tests cover session OpenAPI metadata. No donor test is copied byte for byte and no donor code is
removed, so copied-test counts remain a C3.7 extraction gate.

AISL tier/billing panels, Slack workspace cards, plan-specific dismissal ownership, campaign
categories and site styling remain site-owned. DTC Slack grants, course registration snapshots and
compatibility projections belong to their later package milestones or adoption adapters. The
accounts migration remains provisional and this issue must not create a tag or release.
